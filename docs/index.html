Predicting Organic Search Decay for Content Refresh Prioritization

A decision-support study comparing a client-grouped gradient-boosted model with a transparent staleness heuristic for ranking pages that deserve editorial review first.

Abstract

Can historical search-performance and freshness signals identify content pages that are currently showing organic traffic decline well enough to prioritize editorial review? Using the repository's 30,000-row anonymized content_refresh_anonymized.csv starter release, I constructed an eight-feature representation from 90-day search metrics, content age, update recency, and word count. A HistGradientBoostingClassifier was evaluated with an 80/20 client-grouped split so pages from the same client domain did not appear on both sides of validation, and it was compared with the HIGH_IMP_STALE heuristic baseline. On the recorded validation run, the model achieved 94.0% Precision@50 and ROC-AUC 0.7808, versus 66.0% Precision@50 for the heuristic. The result supports using the model as a ranked editorial-review aid—not as evidence that refreshing a flagged page will cause traffic recovery.

1. Introduction / Problem statement

Editorial teams rarely have enough time to review every page whose organic performance may be weakening. A simple rule such as “high impressions + very old content” is easy to explain, but it can miss interactions between freshness, search visibility, click-through rate, content age, and page size.

The decision this project supports is therefore narrow: which pages should a content team inspect first? The output is a ranked review queue. It is not an automated editing system and it does not attempt to predict Google's ranking algorithm.

Research question. Can historical search-performance metrics and temporal freshness indicators accurately rank pages associated with the trend_direction == "down" outcome, while generalizing across unseen client domains?

3. Methodology

Features

The model uses eight features: content_age_days, days_since_last_update, impressions_90d, avg_position, ctr, word_count, a bounded staleness_ratio, and log_impressions. Missing feature values are median-filled after feature selection.

Label definition

The target is is_declining_label = trend_direction == "down". The notebook reports a 54.21% decline base rate in the 30,000-page dataset.

Model and baseline

The learned model is scikit-learn's HistGradientBoostingClassifier. The baseline is the transparent HIGH_IMP_STALE rule: a page qualifies when impressions_90d ≥ 500 and days_since_last_update ≥ 180.

Validation design

The notebook uses GroupShuffleSplit with test_size=0.2 and random_state=42, grouping by client_hash_id. This keeps a client's pages together and tests whether the model can rank pages for client domains it did not train on.

Leakage checks and boundaries

The target column is excluded from the feature matrix, identifiers are used only for grouping, and the split is client-grouped. The analysis does not claim a causal effect because the label is an observed/proxy outcome rather than the result of a controlled refresh experiment.

5. Limitations & honest framing

  • Proxy label. The target is the observed trend_direction field in the starter dataset, not a future-window traffic decline. It is therefore weaker than a truly forward-looking prediction target.
  • Cross-sectional starter scope. The reported experiment uses 30,000 anonymized page records, not the full 78.8M-row daily warehouse.
  • Non-causal evidence. A high model score means a page resembles pages associated with the decline label. It does not show that editing the page will restore traffic.
  • Seasonality. Expected seasonal demand changes can look like deterioration and may create false positives.
  • Top-3 protection. The notebook identifies 91 validation pages with model probability ≥0.70 and average position ≤3.0; these should be routed to human review rather than automated editing.
  • Single split. The reported validation uses one grouped 80/20 split. Repeated grouped cross-validation or a time-based forward holdout would provide stronger evidence.
Claim boundary: the strongest defensible statement is that this model ranked/flagged the recorded decline label better than the heuristic on the reported client-grouped validation split.

6. Ranked recommendations

  1. Use the model as a review queue, not an auto-editor. Start with pages at P ≥ 0.70 and have an editor confirm the reason for decline before changing content.
  2. Protect strong rankings. Pages at positions 1–3 should receive human review even when the model flags them. Avoid treating a statistical flag as permission to disrupt an already strong placement.
  3. Separate urgent review from monitoring. Use REFRESH_URGENT for P ≥ 0.70, MONITOR_RANK for 0.45 ≤ P < 0.70, and NO_ACTION_HEALTHY below 0.45.
  4. Keep the heuristic as a sanity check. The rule is transparent and useful for detecting surprising model behavior. A production queue should monitor where the model and rule disagree.
  5. Upgrade the target before productionizing. The next research iteration should define features from a prior window and predict decline in a clearly separated future window, with time-aware validation.
